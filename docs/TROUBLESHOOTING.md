# Troubleshooting

---

## The API will not start

```
[Database] Primary MongoDB connection failed (Could not connect to any servers
in your MongoDB Atlas cluster … IP that isn't whitelisted)
[Database] Local Fallback MongoDB Connection Error: connect ECONNREFUSED 127.0.0.1:27017
Failed to start server: MongooseServerSelectionError
```

The API tries Atlas first, then a local `mongod`, then exits. Either:

- **Allow-list your IP** in Atlas → Network Access, or
- **Run MongoDB locally** and point `MONGO_URI` at
  `mongodb://127.0.0.1:27017/guest_house_system`.

Until the API is up, the frontend's landing, sign-in and registration pages
render, but every authenticated screen stays empty — there is nothing to fetch.

---

## Every request fails, or the console shows CORS errors

Check `VITE_APP_BASE_URL` in `.env`:

- It must **end with a trailing slash**. The client appends `api/v1/<path>`, so
  `http://localhost:8000` (no slash) produces `http://localhost:8000api/v1/…`.
- It must be the API **origin**, not the versioned base — `http://localhost:8000/`,
  not `http://localhost:8000/api/v1/`.

Vite only reads `.env` at startup. Restart the dev server after editing it.

---

## Signed in, but immediately bounced back to `/login`

The session query calls `GET /auth/me` with the cookie token. It is dropped when
that returns 401, which means one of:

- The API restarted with a different `JWT_SECRET`, invalidating existing tokens.
- The token is older than its 7-day expiry.
- The browser is blocking the cookie — check that the site is not being served
  from a different origin than the one that set it.

Clear the `stayhub_token` cookie and sign in again.

---

## "Only guests can reserve guest single rooms"

Working as intended. The API pins each role to one room category: `GUEST` users
may take only `SINGLE` guest rooms, `STUDENT` users only `DOUBLE` / `TRIPLE`
bedspaces. Staff roles cannot hold reservations at all, which is why the
catalogue renders read-only for them.

---

## Reserving returns "already reserved for the selected date range"

Another `RESERVED` or `CHECKED_IN` stay overlaps those dates on that room. The
room may still display as `AVAILABLE` if the conflicting stay is in the future —
room status reflects the present, while the overlap check spans the requested
range.

---

## Check-in or check-out is rejected

The status machine allows check-in only from `RESERVED` and check-out only from
`CHECKED_IN`. If the buttons are missing from a ledger row, the current status
does not permit that transition. If a button was visible but the call failed,
someone else changed the reservation first — the list refreshes on success.

---

## The room stayed `OCCUPIED` after check-out

Expected when another active reservation exists on that room; it inherits that
stay's status instead of returning to `AVAILABLE`. Filter the front desk by room
to see what else is open on it.

---

## Editing a room's status did not check anyone out

Also expected, and called out in the edit dialog. `PUT /rooms/:id` writes the
room document only; it does not touch reservations. Use the front desk to move a
stay's status.

---

## `routeTree.gen.ts` is missing, stale, or full of type errors

It is generated by `@tanstack/router-plugin` when the dev server or a build
starts. Never edit it by hand. If it drifts, delete it and run `npm run dev`.

---

## A new route does not appear

- The file must live under `src/routes/` and export
  `Route = createFileRoute("<path>")`.
- The path string must match the file's location exactly, including the trailing
  slash on index routes: `createFileRoute("/dashboard/rooms/")`.
- Files or folders starting with `-` are deliberately excluded from routing.
- Add it to `DASHBOARD_NAV` in `src/utils/navigation.ts` for it to show in the
  sidebar.

---

## The dev server is on the wrong port

The port is set in `vite.config.ts` (`server.port`) and mirrored in
`.claude/launch.json`. Change both. Vite will also fall forward to the next free
port if the configured one is taken — check the terminal output for the URL it
actually bound.

---

## `npm run build` fails with unused-variable errors

`tsconfig.app.json` enables `noUnusedLocals` and `noUnusedParameters` under
`strict`. Commenting out a block while leaving its imports and variables in place
will fail the build. Delete them, or prefix a deliberately unused parameter with
`_`.

---

## Colours look wrong after a change

Nothing in `src/` should reference a raw Tailwind colour (`bg-slate-900`,
`text-blue-500`). Use the semantic tokens — `bg-card`, `text-muted-foreground`,
`bg-primary`. Anything else ignores the theme and breaks in dark mode. See
[UI_GUIDE.md](UI_GUIDE.md).

---

## Dark mode flashes light on load

`initializeTheme()` must run before React mounts — it is called at the top of
`src/main.tsx`. If it was moved into a component, the first paint happens before
the class lands on `<html>`.
